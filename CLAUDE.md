## Commands

- `npm run dev`: dev server at http://localhost:3000 (the journal is at `/journal`)
- `npm run build`: production build, which also runs the TypeScript check
- `npm run lint`: ESLint (flat config with `eslint-config-next` core-web-vitals + typescript)

There is no test suite. `npm run build` is how you check that a change works.

## Architecture

A small Next.js 16 App Router site with no data layer. All content lives in a static TypeScript array.

- `app/journal/entries.ts` holds the `Entry` type (`day`, `date`, `title`, `note`) and the `entries` array. The array is kept oldest first, so new entries go at the end.
- `app/journal/page.tsx` copies the array and sorts it by `day`, newest first, so the order in the file doesn't affect what's displayed. Each card uses `day` as its React `key`, which means `day` must be unique. The card shows a "Day N" label above `title`, so titles shouldn't repeat the day number.
- Dates are ISO strings formatted with `timeZone: "UTC"` so they don't shift by a day in other time zones.
- `next.config.ts` turns on `cacheComponents` and `partialPrefetching`. Tailwind CSS 4 is wired in through a Turbopack loader rule for `*.css` (`@tailwindcss/turbopack`), not PostCSS. `app/globals.css` is just `@import "tailwindcss"`.
- `LayoutProps<"/">` in `app/layout.tsx` is a typed-routes global generated by Next, not an import.

## Journal workflow

- `/journal-entry <title>` (`.claude/skills/journal-entry/SKILL.md`) adds an entry using today's date and recent `git log`, then runs the build. Always pass a title: if you leave it out, `$ARGUMENTS` comes through empty.
- The README's **Progress** table lists every day. Update it whenever you add an entry.
